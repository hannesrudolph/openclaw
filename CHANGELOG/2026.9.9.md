## 2026.9.9


### v2026.9.9

For formatted release notes, [read this release on the docs site](https://docs.openclaw.ai/releases/2026.9.9).

OpenClaw 2026.9.9 fixes several update failures, restores missing iMessage replies, and keeps an old scheduled job from interrupting a newer conversation. It also repairs Windows workspace creation and updates the managed Codex runtime.

**Release scale:** 16 pull requests, 11 direct commits, and 18 contributors.

#### Web UI

The web interface fixes a Windows-specific obstacle to starting fresh sessions.




##### Windows workspaces


With OpenClaw running [natively on Windows](https://docs.openclaw.ai/platforms/windows#native-windows-cli-and-gateway), **New workspace** can now create an empty workspace and start its session without changing your global Git settings. Install Git for Windows and make it available on `PATH` first. Deeply nested workspace paths can still hit a separate Git limit.



###### Sources and complete change list


**Bug fixes**

- Restore empty workspace creation on native Windows by using a null-configuration path that Git accepts, while keeping each workspace in its own repository. [#164202](https://github.com/openclaw/openclaw/pull/164202)

**Documentation**

- Document native Windows workspace support and the Git for Windows prerequisite.

**Limits and compatibility**

- A separate Git metadata-argument limit still affects deeply nested paths. Native validation used a short temporary root.







#### Updates and Maintenance

Updates address specific failures that could stop an upgrade while checking an active database or converting older data.




##### Update completion


Updates could fail at the start or end while the Gateway was writing to its database. That activity no longer blocks the update’s ownership checks. Updates from affected older builds also preserve the files needed to finish plugin migrations after the package is replaced.



###### Sources and complete change list


**Bug fixes**

- Read database ownership without copying the entire active database, preserving existing writer transactions. [30c180a](https://github.com/openclaw/openclaw/commit/30c180a4ece3ae149286b80174b0edb526aa88ae) by [@RomneyDa](https://github.com/RomneyDa).
- Preserve deferred plugin migration dependencies across package replacement when updating from affected earlier builds. [ecac0d3](https://github.com/openclaw/openclaw/commit/ecac0d3f0bdca5d127df1b4f269d007714697ce4).

**Limits and compatibility**

- The ownership repair applies to the update's ownership checks. State owned elsewhere, malformed ownership metadata and restricted database access still cause a refusal; migration requirements remain separate.






##### Backups on FUSE storage


On FUSE storage, backups and restores used by updates, Doctor and rollback can proceed when only a file's timestamps have drifted. OpenClaw rechecks the contents before accepting the backup, as described in the [container upgrade guidance](https://docs.openclaw.ai/install/docker#upgrading-container-images).



###### Sources and complete change list


**Bug fixes**

- Accept timestamp-only changes after verifying that the backup contents still match, including restored-database publication. [3ecb62a](https://github.com/openclaw/openclaw/commit/3ecb62aad260e3f871e7ae83d446404abfc83bed).

**Limits and compatibility**

- Changed contents, file identities, birthtimes, sizes and integrity failures still cause a refusal.






##### Memory-cache migration


Doctor can convert older memory caches containing oversized or malformed entries by skipping those entries and reporting recoverable warnings. Skipped cache entries rebuild as needed; your source data is retained.

For an older database upgrade, follow the [migration guidance](https://docs.openclaw.ai/reference/database-schemas/agent-schema-history#compact-agent-payload-storage), including stopping writers and taking a verified backup first.



###### Sources and complete change list


**Bug fixes**

- Keep oversized or invalid cached embeddings from aborting Doctor's conversion, with bounded reads and warnings for skipped entries. [#164303](https://github.com/openclaw/openclaw/pull/164303).

**Limits and compatibility**

- Conversion processes 128-row windows and skips invalid vectors or cache entries larger than 1 MiB. Valid entries retain their identities, provider and model metadata, dimensions and timestamps.
- An interrupted conversion retains transaction rollback, and rerunning a completed conversion performs no writes. This repair is specific to legacy cache conversion.







#### Messaging

Messaging fixes address missing replies and task results that appeared in chat but were still marked as failed. Telegram users also have a command change to make when opening the Control UI.




##### Telegram Control UI


Use `/controlui` in a bot DM to open the Telegram Mini App. `/dashboard` creates or updates a session dashboard. If you used the older Mini App command, update saved instructions, shortcuts and custom bot-menu descriptions, then request a fresh `/controlui` button. The [migration guide](https://docs.openclaw.ai/channels/telegram/mini-app#upgrading-from-dashboard) covers the change.

Wildcard-only access groups no longer grant Mini App access. If that affects you, ask your administrator to add your explicit numeric Telegram ID to the bot account's owner access list or a referenced Telegram access group, keeping existing entries.



###### Sources and complete change list


**Bug fixes**

- Separate the Mini App launcher from session dashboards and update launch, expired-link and HTTPS recovery messages. [#161369](https://github.com/openclaw/openclaw/pull/161369) by [@mmaps](https://github.com/mmaps), with command separation by [@joshavant](https://github.com/joshavant).

**Security and trust**

- Require explicit numeric owner matching during both launch and authentication. Administrators can add the ID to the selected account's effective `allowFrom`, `commands.ownerAllowFrom`, or the Telegram members of an access group referenced by an owner list. Wildcards and usernames do not qualify.

**Documentation**

- Update Telegram Mini App and web dashboard guidance, retain the earlier Mini App anchor, and align the Chinese glossary with Control UI terminology.

**Limits and compatibility**

- Registered bot commands refresh when the Telegram account starts. Existing Mini App URLs and Tailscale settings remain usable.
- Recorded native rendering checks covered macOS Telegram Desktop. The session-dashboard check demonstrated command dispatch with a mock model, not creation of a dashboard artifact.






##### iMessage replies


Ordinary iMessage conversations could finish generating an answer without sending it. The affected delivery path now sends the final reply, with no configuration or data migration required.



###### Sources and complete change list


**Bug fixes**

- Restore final delivery when an ordinary agent turn uses a prepared view of the current plugin registry. Preserve message receipts, clear the completed delivery record and avoid leaving a retry queued. [#163742](https://github.com/openclaw/openclaw/pull/163742), with coauthors [@VACInc](https://github.com/VACInc) and [@Kimiyu-186](https://github.com/Kimiyu-186).

**Documentation**

- Clarify in the channel-plugin SDK guidance that these ordinary replies use the live channel registry without a reload handoff callback.

**Limits and compatibility**

- Actual plugin reloads retain their separate handoff requirements and checks for changed senders, registrations, settings and runtime owners.
- Recorded regression checks substituted the Apple RPC boundary; they did not demonstrate a live iMessage send.






##### Discord task results


When a delegated task successfully posts its result to your Discord thread and then finishes silently, that result can now count as delivered. This fixes the contradictory failed status that could remain even though the reply was already in the thread.



###### Sources and complete change list


**Bug fixes**

- Recognize a successful message-tool reply to the requester's own thread when settling delegated work. Webhook-bound replies also follow that thread's webhook and persona. [#163756](https://github.com/openclaw/openclaw/pull/163756) by [@MertBasar0](https://github.com/MertBasar0), reported by [@stuart-minion-ai](https://github.com/stuart-minion-ai) and landed by [@obviyus](https://github.com/obviyus).

**Limits and compatibility**

- Messages sent to a parent channel, sibling thread or user do not count as delivery to the requester thread. Automatic-reply-mode finalization is unchanged.
- Misleading recovered-requester error wording and the separate physical-thread-receipt follow-up are outside this repair. Recorded runtime checks used isolated local Discord endpoints, not live Discord.






##### Queued messages


Cancelling a queued message that has not started processing now releases the hold that could prevent the reply already running from finishing, without stopping that active reply.

A remaining race affects cancellation while plugin work is pending. That work can continue while the session is reset or deleted; this update does not resolve that overlap.



###### Sources and complete change list


**Bug fixes**

- Release an idle cancelled request's borrowed session reservation while preserving the active request. The shared change applies beyond a single messaging channel. [#164230](https://github.com/openclaw/openclaw/pull/164230) by [@vincentkoc](https://github.com/vincentkoc).

**Limits and compatibility**

- The author's [post-merge limitation report](https://github.com/openclaw/openclaw/pull/164230#issuecomment-5968104212) is contextual evidence for the unresolved plugin race. Pending inbound plugin work can outlive the released reservation when no independent lease protects the session. No completed follow-up repair is established.
- The regression covers an idle cancelled successor and preservation of its active predecessor. It does not cover pending plugin claims or an end-to-end completed reply.







#### Models and Providers

The Codex runtime bundled with OpenClaw receives fixes for starting sessions and finishing interrupted work.




##### Managed Codex


OpenClaw now bundles Codex 0.160.0, including upstream startup and logging fixes. When Codex’s Guardian checks repeatedly refuse an action, the turn can now end without hanging until it times out. The managed catalog also recognizes GPT-6.1 Sol for eligible accounts; model access still depends on your account and the configured [Codex runtime](https://docs.openclaw.ai/providers/openai/runtimes).



###### Sources and complete change list


**Improvements**

- Updated the managed Codex catalog to recognize GPT-6.1 Sol and corrected completion handling for turns interrupted by repeated Guardian denials. The runtime, ACP dependency, model-discovery version hint, protocol schemas and documentation were aligned in [65e89fc](https://github.com/openclaw/openclaw/commit/65e89fcc277cd26cf2f763112eaeb36325834a0e). By [IstiqlalBhat](https://github.com/IstiqlalBhat), with coauthor [RomneyDa](https://github.com/RomneyDa) and credited contributor [fuller-stack-dev](https://github.com/fuller-stack-dev).

**Bug fixes**

- Advanced the managed runtime and ACP dependency to 0.160.0, bringing upstream SQLite connection and logging fixes while keeping the documented model catalog unchanged. Platform dependencies, fixtures and documentation were updated together in [#163560](https://github.com/openclaw/openclaw/pull/163560). By [vincentkoc](https://github.com/vincentkoc).

**Limits and compatibility**

- Catalog visibility does not grant model access or change your selected model. Complete GPT-6.1 Sol routing also depends on the complementary provider support described in [#161400](https://github.com/openclaw/openclaw/pull/161400), linked here as context.
- Custom, remote and macOS desktop-owned app-servers retain the 0.149.0 minimum. Updating a separate Codex CLI does not update OpenClaw’s managed runtime.
- The runtime update does not establish a fix for every initialization timeout or Bun issue. Reported checks did not establish authenticated inference, all-platform compatibility or clean joined shutdown. Newly generated protocol fields alone do not add OpenClaw controls.







#### Automations and Scheduling

These fixes address ways background work could interrupt an active conversation.




##### Scheduled jobs and active conversations


A scheduled job's old timeout no longer stops a newer conversation using the same session or clears that conversation's tools. Jobs that reach their own timeout still stop as expected, with no settings change needed.



###### Sources and complete change list


**Bug fixes**

- Keep an expired scheduled job from cancelling a later conversation or removing its tools. [#163704](https://github.com/openclaw/openclaw/pull/163704) Thanks to [@jayzhou2309](https://github.com/jayzhou2309) for the fix and tests, [@AXEG0](https://github.com/AXEG0) for reporting the incident, [@ekinnee](https://github.com/ekinnee) and [@MasterSwords1](https://github.com/MasterSwords1) for investigating the cancellation boundary, and [@obviyus](https://github.com/obviyus) for validation and landing work.

**Limits and compatibility**

- The repair addresses cancellation of the wrong run in the [reported incident](https://github.com/openclaw/openclaw/issues/163568). The original job's pending completion, result delivery and subsequent transcript-write failure remain outside this fix.






##### Background job startup


Background Skill Workshop reviews and scheduled jobs can now start without repeating plugin setup that could stall chat or disconnect the Control UI. This applies to jobs linked to their agent's configured workspace, and [file access stays limited to the task folder](https://docs.openclaw.ai/plugins/architecture#plugin-metadata-snapshot-and-lookup-table).



###### Sources and complete change list


**Bug fixes**

- Reuse prepared plugins for eligible background jobs, including during conversation compaction, while retaining task-folder file restrictions. [#164049](https://github.com/openclaw/openclaw/pull/164049)

**Limits and compatibility**

- Reuse requires an explicit bootstrap workspace that resolves to the configured agent's canonical workspace without fallback. Other workspaces retain their own plugin runtime. No configuration migration is required.
- The reported startup comparison measured a test fixture before model inference, so it does not establish a general speed improvement or eliminate every cause of chat stalls.







#### Security and Privacy

Input policies now cover OpenClaw sessions on paired computers, while the optional Windows sandbox gets a compatibility repair.




##### Windows MXC sandbox


The optional [MXC sandbox](https://docs.openclaw.ai/plugins/reference/mxc) can activate and run tools on compatible Windows hosts without the retired Windows service it previously required. If you use a custom MXC executable, update it to an MXC 0.8.0-compatible version or remove the override, then restart the Gateway.

Host users with process-inspection rights can still inspect MXC request arguments, including command and environment data. Keep secrets out of MXC command arguments and environment values.



###### Sources and complete change list


**Bug fixes**

- Restore Windows MXC activation and command execution by checking the selected executor and correcting its command configuration. [#158303](https://github.com/openclaw/openclaw/pull/158303) Thanks [@paulcam206](https://github.com/paulcam206).

**Limits and compatibility**

- Custom executors must support `--probe`. To return to the bundled executor, run `openclaw config unset plugins.entries.mxc.config.mxcBinaryPath`, then restart the Gateway. If its probe also fails, address the reported host-readiness error before retrying.
- The current plugin requires OpenClaw plugin API 2026.9.6 or newer, distinct from the minimum install host of 2026.6.11. Supported degraded isolation tiers warn without blocking activation.
- Reported Windows x64 execution covered `workspaceAccess=none` at an earlier PR revision. Read-write configuration had native dry-run validation, not equivalent runtime proof.






##### Input policies on paired computers


Plugin [input policies](https://docs.openclaw.ai/plugins/hooks#choose-a-hook) can now stop an OpenClaw request before it runs on a paired computer. A rejection or policy error blocks the turn and leaves the session available for another request. Policies inspect the initiating prompt and history available at the Gateway. If your policy needs system instructions or skill context assembled later on the paired computer, keep using a supported local runner.



###### Sources and complete change list


**Security and trust**

- Enforce plugin input policies before node execution and Gateway approval of the input, with cancellation and authorization rechecks after the policy runs. [#164270](https://github.com/openclaw/openclaw/pull/164270)

**Limits and compatibility**

- When the Gateway still controls saving the input, a blocked turn saves a redacted block message. Input already saved by the calling transport remains in the transcript.
- This applies to OpenClaw node worker turns, not Codex or Copilot input gating, and does not extend support to other lifecycle hooks or change pending-input retention.
- Reported live checks used isolated loopback nodes. They do not establish physical-device or wide-area-network validation or a speed improvement.







#### Other Bug Fixes

These fixes address blocked session creation and interruptions while running conversations or finishing commands.




##### Windows session storage


Saved sessions can now be created when a Windows junction or another filesystem alias points to the session database. OpenClaw recognizes that the different paths lead to the same database, avoiding a false ownership error.



###### Sources and complete change list


**Bug fixes**

- Recognize equivalent session-database paths during creation and retain the selected storage aliases for new sessions. [bec0cfd](https://github.com/openclaw/openclaw/commit/bec0cfd9a21a1e6d5900fd0ac859c23f56b45d87) by [@cestercian](https://github.com/cestercian), with coauthor [@RomneyDa](https://github.com/RomneyDa).

**Limits and compatibility**

- The selected database, agent and session key must still match. This repair addresses aliased storage paths, not every Windows session-creation failure.






##### Command shutdown


OpenClaw works around a Node shutdown bug that could leave a command stuck after it printed all its output. The change also covers the Gateway service, hook relays and the macOS node worker. Some command runs may take longer with the workaround enabled. The [Node compatibility guide](https://docs.openclaw.ai/install/node-compatibility#v8-compiler-settings) explains the runtime settings and advanced overrides.



###### Sources and complete change list


**Bug fixes**

- Disable the Node compilers involved in the shutdown race at supported executable entrypoints. [#163788](https://github.com/openclaw/openclaw/pull/163788)

**Limits and compatibility**

- Explicit `--maglev` or `--concurrent-sparkplug` Node flags keep the corresponding compiler enabled and bypass that part of the workaround. Bun and library imports retain their existing behavior; separate Gateway worker entrypoints are outside this repair.
- Reported CLI wall time increased by about 5% in sequential runs and 10–20% under eight-way load on the tested four-vCPU machines. Those measurements are specific to that test setup.






##### Sessions on paired computers


Concurrent [sessions on paired computers](https://docs.openclaw.ai/nodes/session-hosting) can continue while the host reports its available capacity and other routine status information. These updates could previously make a connected computer appear unavailable, stalling or failing another session. Updating the Gateway applies the fix without changing node settings or pairing the computer again.



###### Sources and complete change list


**Bug fixes**

- Keep connected session hosts available during capacity, host-statistics and skill-bin metadata updates. [#164087](https://github.com/openclaw/openclaw/pull/164087)

**Limits and compatibility**

- The change applies to those routine metadata writes. Revocation, approval and current-owner checks continue to control whether a host may run work.
